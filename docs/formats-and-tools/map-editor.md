# The map editor

Part of [Formats and tools](../formats-and-tools.md).

`MapEditor/` edits map and level JSON (drag-and-drop a file onto the window). **It draws the map as the game does** (#1210): the balls, the game's sky and the scene, and round the field the setting a session hangs it in (the island with its glass drain and pit under it, the ceiling glass and its rigging over it), in the scene's point lights and the sun's shadows, with the same instanced procedural spheres, shaders, sky-derived light and HDR pipeline, from the compiled shaders in `Prazsky.Shaders`. **G**, **I** and **C** switch the game's sky, the island and the ceiling glass off and on, each a view and never data ([below](#the-setting-and-the-games-frame-1210)). It has **no GUI of its own** since #522, no gun and no physics; the field is also marked by a translucent outline (`GUI/AABB.cs`, `WireBoxMesh`).

## Keys

**F2** (or a file dropped on the window) opens a map or level; **F4** saves a level (map + scene + sky + ball material + the loaded `music`, `author`, `crates`, `softness`, `weather`), **F1** the map alone, **F3** starts a new one. **B** cycles sky domes (the game's NumPad1; here NumPad1–9 pick ball colours and NumPad +/− cycle all thirteen). **V** cycles all twenty-one scenes, **L** the ball material, **K** the kind of the next placed ball; **G** switches the game's sky (the plain dome with it off), **I** the island, **C** the ceiling glass (one line of the help for the three, which the status line answers by name); N fills, M clears, W/A/S/D/Q/E fly the camera, F8 saves a screenshot, **H** folds the key help.

**What the screen shows.** The top line is the shared `InfoRenderer`: the FPS and a status line naming what the last key did (the colour, kind, material, scene or level). Under it is the editor's own key help (`GUI/KeyHelpOverlay.cs`, #1209). It is grouped (FILE, then the H line, SELECTOR, BALLS, CAMERA, SCENE, WINDOW) and drawn on a dark see-through panel, with every description starting at one x. **The file keys come first and stay on screen when H folds the rest**, so how to open and save a level is never off the screen. The axis cross (`GUI/AxisGizmo.cs`) stands in the bottom-right corner, clear of the panel at the usual window sizes; a small window that needs the help in several columns can spread the panel over it, and the help, drawn after, covers it.

- **It fits the window at any size** (`GUI/KeyHelpLayout.cs`). Text is 0.6 × the font at a 2160-line window, in proportion below that, and never smaller than an 18-pixel line while there is room. The groups flow into as many columns as that needs, a group never split between two; only when no number of columns fits does the text shrink. The window can be dragged to any size, so this is arithmetic, not a minimum size. `MapEditorKeyHelpTests` holds every line inside the window over a sweep of sizes from 100 × 60 to 3840 × 2160.
- **`GUI/EditorKeyHelp.cs` is the authority for the wording**, and each binding in `MapEditor.Initialize` names the line that documents it (`Bind(EditorKeyHelp.X, key, method)`), so no key can be bound without a line. A new line goes into `EditorKeyHelp.All`, which is what is drawn; a test fails on a line left out of it. The font has Latin-1 and Latin Extended-A only, so an en dash or an ellipsis there draws as `?` (a test checks).
- The help names the axis, never the members: "Next scene (named at the top)", not a list of scenes, so a new scene, material or kind cannot make it wrong (#320, #376).

- **V, L and K walk the enums** (`SceneRenderer.NextScene`, `BallStyles.Next`, `BallKinds.Next`), so a new scene, style or kind is reachable the moment it is declared. (A fixed prefix once left fifty shipped levels' scenes unreachable, with no way back to the level's own scene except reloading.)
- **V does not adopt the scene's default dome** (the Testbed does): here the dome is *data* that F4 writes, and overwriting it on a cycle would destroy the author's choice.
- **K is its own key** because kind and colour are orthogonal (a rock is not a fourteenth colour); they compose with nothing added. ⚠ The status line names each kind in a `switch` (`CycleBallKind`): a new kind needs its case.

## The command line

`MapEditor.exe [file] [width=W] [height=H] [shot=s1,s2,…] [campos=x,y,z] [camtarget=x,y,z] [notext] [gamesky=off] [island=off] [glass=off] [save=path]`. The first argument that is not an option is the map or level to open. `width=`/`height=` size the window's client area (1280 × 800 without them). `campos=`/`camtarget=` place the camera in the editor's grid frame (the selector's: a cell's raw position, the map not centred), and R returns there; `notext` starts with the text hidden, as F12 hides it. `gamesky=`, `island=` and `glass=` (`on`/`off`) start a view switch as G, I and C leave it. `save=` writes the file opened on the command line back out as F4 writes a level, once it is applied, and prints the `[level] Saved` line: the same level saved with the switches on and off is the same file, which is how a run shows the switches are a view. `shot=` writes the back buffer to `Screenshots\mapeditor-<time>-<scene>.png` beside the exe at those seconds of the draw clock (the shared `ScreenshotWriter`, printing a `[shot] <path>` line). Use it to photograph the editor: its `Update` stops while the window is not active, but the draw and the shot carry on, so a scripted run needs no focus, and nothing in front of the window gets into the picture. An argument counts as an option only by its exact prefix, so a file path stays a file path. The open and save dialogs start in the working directory, so a scripted run gets a scratch one.

## The render pipeline

`MapEditor.Draw` is the Game's frame (`BS3DGame.BeginSceneDraw` and the session's draw after it) less the gun, the shots and the effects of play. The sun's shadow map first (`SceneRenderer.DrawShadowMaps`, the balls collected before it so they cast); then, with the game's sky up, the deck on the instanced effect and the sky's own targets (`SkyPass.Prepare`); the shared supersampled HDR target (`SUPERSAMPLE_FACTOR` fixed at 2, no `ssaa=`) cleared to the **current dome's horizon colour** (`_rig.HorizonLinear`; black for a sky-replacing scene: at a wide aspect the bottom corners look below the horizon past dome and scene, and a fixed blue showed through); the island's depth before the environment (#1098), the environment's opaque half and the wood, the game's sky **behind the opaque scene** (#1104), the aurora's wood, the environment's blended half and the outback's shimmer, the island and its pit, the balls, the rigging, the outline, the drain's glass and the ceiling's pane, the fires and the snow; and `PostProcessPipeline.Resolve` runs `Glare.fx` and `Tonemap.fx` with the game's own look figures.

- **Balls** go through the shared `BallRenderSet` (#76): the game's albedo, emission, translucency and heartbeat, with no landing **ripple** (`ripples: false`).
- **The game's sky** is the Game's: `SkyDome` with `Sky.fx` as its effect (the sun's disc, the cloud deck), the heaps over it where the Game draws them (`CloudVolumes`, on the authored detail the editor draws), the deck's shadows on the ground, the island and the balls through the one `CloudField`, and the volcano's crater lighting the deck from below. Its weather is the level's (`WeatherLooks.ForLevel`: the level's word, else the scene's own), put up **at once** on a load, a new map or V, where the Game fades into a level's sky.
- ⚠ **The plain dome** (G off) is `SkyDome`'s own `BasicEffect` gradient drawn first over the clear (`linearVertexColors: true`, since it goes into the linear target), with the deck's coverage zeroed on every effect (`CloudField.SuppressOn`, through the rig's cloud hook): an effect keeps its last values between frames, and a deck left on one would shadow the ground under a sky with no cloud in it. The editor never steps the overcast (`SkyLightRig.StepOvercast`), as the Game never does.
- **The light rig** is the shared `SkyLightRig`: `ApplySkyLighting` lights the balls, the city, the wood, the lamps, the island (not its pit) and the rigging, and `ApplyToGlass` the pane, whether or not a switch shows them, so a switch turned on shows them in the sky they stand under. The scene's point lights (`SceneLights`: the campfire, the neon, the forest's lamps) fall on the island and the balls as in the game.
- **The AABB outline** is depth-tested with its flat colour linearised on the CPU (`ColorSpace.SrgbToLinear(COLOR)`, or it tonemaps too bright). **The selector** (additive, depth off) and the **axis gizmo** (`GUI/AxisGizmo.cs`) are drawn *after* the resolve, in display space, where `BasicEffect`'s gamma is right.

## The setting and the game's frame (#1210)

The owner: "In the map editor the map will also have to be drawn as in the game, including the sky and the island. Both will be possible to switch off." So the editor draws what a player sees round a level, and the author can still see the whole cluster against the plain sky or with nothing under it.

- **Two frames.** The editor keeps a map in its raw grid frame (the selector, the outline, the six views, the flying camera and `campos=` all work there, the map never centred). The setting and the balls stand in the frame a session hangs the field in: the middle of the top level on the island's axis, the top at `ClusterHang.FIELD_TOP_Y` or raised past the death line. They are drawn through `GameFrameCamera`, the editor's camera moved by the field's hang (`ClusterHang.FitWorldOffset` of the **uncentred** map, which equals what a session adds to the centred one), taken once a frame (`Follow`), so the two lenses' draws meet on the screen and in the depth buffer. The balls go in at the hang (`BallDrawFrame.AddMap(map, offset)`), so the shadow map, the deck's shadow, the island's ground term and the sea's fade see them where the game does. `MapEditorGameFrameTests` holds every cell of four fields to a session's position, and the moved lens to the editor's.
- **The scene stands where it stands in play**, round the island's axis, whatever the switches say: with the island off the field still hangs over the middle of the scene's clearing. The two cities clear the island's radius (`ArenaIsland.RADIUS`, the Game's figure).
- **G, the game's sky** ([above](#the-render-pipeline)), or the plain dome.
- **I, the island**: the shared `ArenaIsland` (stone, drum, glass drain and gold bands, the pit shaft in the solid-terrain scenes), drawn in the Game's slices, and the hole the solid terrains cut for it (`SceneRenderer.TerrainHoleRadius` is `ArenaIsland.TERRAIN_HOLE_RADIUS`, 0 with it off, so the ground stays whole under the field). It casts into the sun's map while shown.
- **C, the ceiling glass**: `CeilingPlate` fitted to the field (`FootprintFor`) and hung `CentreYAbove` the field's top, with its `CeilingRigging` and its faint shadow (`CastCeilingShadow`). It is the plain translucent pane the Testbed draws: the Game alone bends what is behind it ("Glass" in `docs/rendering.md`). The owner named the sky and the island; the plate is a third switch because an author looking down into a cluster may want the glass out of the way.
- **The shadows** are cast by what the editor draws, as the Game's casters are: the island (with I on), the balls, the forest's wood and lamps, the aurora's wood and the cities' towers, besides the backdrop's own planting.
- **A switch is a view, not data.** None of them is read by F4's write (`SaveLevelTo`): the dome, the scene and the weather a level carries are the ones it was loaded with, whatever is drawn. The same level saved by `save=` with the switches on and with them off is the same file to the byte.
- **The cost** stays inside an interactive frame: at 1600 x 900 the editor held its 75 Hz vsync with everything on (the desktop, its GPU shared with other work). It is not measured against a tier's budget: the editor has no tier and draws the authored detail.

## The scene-config panel, removed in #522

From #45 to #522 a Myra `PropertyGrid` over the active `SceneConfig` (G toggled it) tuned a scene live. **It was removed because a scene's look is programmed, not configured** (the owner's ruling): a level names its scene, the parameters are fixed in code, and a per-run editor of shader and material parameters is not wanted. With it went Myra from the editor, `SceneRenderer.Apply(SceneConfig)` and both `Replant` methods; `Rgb`/`Vec2`/`Vec3` are `readonly struct`s again (they were classes only because the grid edited a boxed copy). **The configs' shape outlived it** (named nested groups such as `NebulaOne`/`Two`/`Three`, the storm's `Clouds`/`Surface`/`Flash`/`Air`): a named group reads as a config where an index does not, but no document should justify it by the grid's old limit.

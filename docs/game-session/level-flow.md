# A level from start to end

Part of [The game: a session](../game-session.md).

## Winning and the phase

- **Clearing the field wins** when `BallsMap.GetRemovableBallsCount() == 0`, tested **only on a landing** (`CheckLevelCleared`: polling would declare a ball-less authored level won before a shot). It is the *removable* count (#323), not the ball count: a standing `BallKind.Rock` would never end the level while the out-of-shots test, reading the same count, declared it lost. What is left at zero is cut loose (`ReleaseAllBalls`) for no score; the end is held `LEVEL_CLEARED_BEAT` so the collapse is seen.
- **`LevelPhase` is the one explicit flow** (`Prazsky.BS3D/Levels/LevelPhase.cs`, written only by `GameplayScreen.EnterPhase`): `Playing` -> `ClearedBeat` -> `Over`; `Playing` -> `LossHold` -> `Over` (line crossed with the flight engaged); `Playing` -> `Over` (budget spent). `EnterPhase` refuses transitions `LevelPhases.CanEnter` forbids, logged `[phase] REFUSED ...`, never thrown; legal ones print `[phase] <from> -> <to>`. It owns the entry work: `ClearedBeat` arms the countdown, freezes the figures the score service is told, starts the celebration; `Over` shows the result page (`ShowResultScreen`, called from nowhere else).
- `LevelDecided` is `phase != Playing`: `Shoot`, the preview and the transmute refuse on it (a shot used to be scored spent against a won level). ⚠ **`LevelOver` (`LossHold` or `Over`) is the line past which the arithmetic is read-only**: a late landing scores nothing, a culled shot no miss, the ball sticks silently. It covers the loss's ~1.7 s hold before the page exists, and is **not** true in the cleared beat (a late landing still scores). A countdown doubling as a state flag started the celebration twice once the result page stopped freezing the screen; that is why the phase exists.
- **`BuildLevel(index)` is the one path** for Play, New Game, retry and advance. `FinishLevel` marks the clear and shows the result page whose buttons hold build, teardown and advance (Next Level only when a next entry exists **and** the star total opens it). It runs **last** in `Update`: an ending may tear the session down.

## Losing

A level is lost when the budget is spent uncleared, or the glass pushes the cluster past the death line (`[ceiling] Step to ...`, `[level] Lost ... ClusterReachedLine`).

- ⚠ **The implied limit is one sum nothing checks**: `final headroom = clearance - floor(shots / ceilingStep) * CEILING_DESCENT_PER_STEP` (clearance is the `[field]` line's "above the line"). It must clear a swing (deepest measured 0.82). Negative means the last shots cannot be played however well aimed. The sag gate ("The sag probe" in `docs/formats-and-tools.md`) measures the rest.
- **A cluster that merely swings has not lost** (#239). The loss test reads the lowest ball's live pose, which oscillates about the descending trend. A ball past the line by more than `ClusterHang.SWING_ALLOWANCE` loses at once; otherwise it must be **held** below for `ClusterHang.BELOW_LINE_GRACE` (1.5 s, the player's last-chance window; the depth clause has none) without once coming back up. One copy, `ClusterLineWatch`, shared with `SagProbe`. The death line cannot go below `ArenaIsland.TOP_Y + 1` without the laser net drawing inside the island cap. `SagProbe.SHOT_SECONDS` leaves 0.1 s past the grace: a longer grace must raise it. `[level] Lost` says which clause fired.
- **Rules ride the world's clock** (#577): the line check reads the simulated seconds (`_simulatedThisFrame`) and the glass slides inside the step loop (`SlideCeiling`); presentation (cleared countdown, step hold, flash) stays on the wall clock.

## The start swing and soft lattices

- **The cluster springs from the glass at start, on purpose** (#617). `PhysicsWorld.BeginStartSwing` softens **only the sockets to the glass** for `ClusterStartSwing.HOLD_SECONDS`, eases back over `EASE_SECONDS`, at a frequency solved per level from the load each carries; the Testbed and sag gate call it after `BuildBallsStructure`, the Game when it lets the cluster go (`ReleaseCluster`). ⚠ Softening every socket is wrong (a strand is springs in series and sagged 8-13 units through the line). **It waits for the lens** (#690): while a chapter's opening tour runs (`ChapterIntro.Running`) **the world is not stepped at all**. `[swing]` and `[softness]` print at the release.
- **Soft lattices** (#690): `LatticeSoftness` gives ball-to-ball sockets a spring of their own (`softness=<Hz>[:<damping>]` in the Testbed, `--softness=` in LevelGen, a level's `Softness`; prototypes `Testbed/Maps/Sag_*.json`). ⚠ The builder's own spring already sags a long thin span, so rope or cloth is first a question of *shape*; softer is deeper and never unstable, but **the line limits it**: a chapter softer than the builder needs deeper fields or its own line.
